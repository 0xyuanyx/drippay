# DripPay 제품 기획

## 한 문장

**DripPay는 선불 구독 포인트를 한 번에 넘기지 않고, 이용 시간이 흐른 만큼만 정산하는 지갑 기반 정산 엔진이다.**

## 해결하려는 문제

공동 이용 비용을 먼저 한 번에 송금하면 파티원은 남은 기간의 비용을 보호받기 어렵습니다. 반대로 파티장은 시간이 지나도 비용을 받지 못할 수 있습니다. DripPay는 포인트를 중간에 보관하고, 시간 비례 규칙으로 두 사람의 권리를 분리합니다.

## 사용자와 가치

| 사용자 | 하는 일 | 얻는 가치 |
| --- | --- | --- |
| 파티장 | 조건 생성, 경과분 출금 | 이미 제공한 기간만큼만 받을 수 있음 |
| 파티원 | 포인트 예치, 필요 시 취소 | 남은 기간의 포인트가 한 번에 넘어가지 않음 |

## 차별점

피클플러스 같은 공동구독 운영 서비스가 매칭·계정 관리·월 결제를 다룬다면, DripPay는 그중 **정산 규칙**에 집중합니다. 파티를 찾거나 OTT 계정을 제공하지 않습니다. 돈이 언제 누구에게 귀속되는지 컨트랙트가 공개적으로 계산하는 것이 핵심입니다.

## MVP 사용자 흐름

### 파티장

1. MetaMask를 Hardhat Local에 연결한다.
2. `새 정산 만들기`에서 `파티장으로 시작`을 고른다.
3. 고정 플랜을 선택한다.
4. 생성된 참여 코드를 파티원에게 전달한다.
5. 시간이 흐른 뒤 `받을 돈 출금`으로 경과분을 받는다.

### 파티원

1. `새 정산 만들기`에서 `파티원으로 참여`를 고른다.
2. 참여 코드를 입력해 금액·기간을 확인한다.
3. 포인트 사용을 승인하고 예치한다.
4. 남은 예치금을 확인한다.
5. 중단하려면 `정산 취소 및 잔액 반환`을 누른다.

## 고정 플랜 이유

MVP는 가격 협상 서비스가 아니라 시간 정산 규칙을 검증합니다. 따라서 서비스명·금액·기간을 생성 후 바꿀 수 없게 두고, 커스텀 금액도 UI에서 제외했습니다. 다음 단계에서 운영자가 서비스 플랜을 추가하는 방식으로 확장합니다.

## 성공 기준

- 30일·10,000P 계약이 15일 후 정확히 5,000P / 5,000P로 나뉜다.
- 잘못되었거나 이미 사용한 참여 코드는 예치 전에 거절된다.
- 홈에서 역할, 누적 정산 포인트, 진행률, 받을 돈, 남은 예치금을 바로 이해할 수 있다.

## 후속 계획

1. 운영자 플랜 카탈로그와 참여 코드 만료
2. 다인 파티, 좌석 수, 대기자 교체
3. 자동 실행 서비스(keeper)를 이용한 경과분 자동 출금
4. 포인트 부족 시 자동 충전 제안 및 결제 BM
5. 공식 이용권·제휴가 가능한 서비스만 별도 연동

자동 출금은 컨트랙트만으로 시간을 맞춰 스스로 실행할 수 없으므로, 별도 자동화 주체와 가스비 정책이 필요합니다.
