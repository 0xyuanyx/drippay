# 시간정산 MVP 설계 명세

## 1. 제품 정의

**시간정산**은 공동구독 플랫폼이 아니라, 선불 구독료를 ERC-20 포인트로 예치하고 이용 기간에 따라 자동 분배하는 정산 엔진 MVP다. 파티원은 미래 기간의 포인트를 보호받고, 파티장은 실제로 경과한 기간만큼만 인출할 수 있다.

이 MVP는 OTT 계정·비밀번호 발급, 실제 접근 권한 검증, 파티 자동 매칭을 제공하지 않는다. `Netflix`, `Disney+` 같은 이름은 정산 사유를 구별하는 메타데이터일 뿐이며 특정 사업자와의 제휴나 계정 공유를 의미하지 않는다.

## 2. 문제와 차별점

기존 공동구독 서비스는 파티 매칭과 월별 자동 정산을 중심으로 한다. 시간정산은 그 서비스를 대체하지 않는다. 대신 선불금이 한 번에 파티장에게 넘어가지 않고, 스마트컨트랙트 안에서 시간에 비례해 잠금 해제되는 정산 규칙을 검증한다.

| 구분 | 기존 공동구독 운영 서비스 | 시간정산 MVP |
|---|---|---|
| 핵심 역할 | 매칭·결제·운영 | 예치금 보관·시간 기반 분배 |
| 지급 시점 | 월 단위 자동 정산 | 경과 기간만큼만 인출 가능 |
| 파티원 보호 | 운영 정책·보증 | 미래 기간 포인트는 컨트랙트에 남음 |
| MVP 범위 | 계정·파티 운영 | ERC-20 정산 규칙과 대시보드 |

발표에서 증명할 메시지는 하나다.

> 예치된 10,000 포인트 중 15일이 지나면 파티장은 5,000 포인트만 받을 수 있고, 파티원에게는 5,000 포인트가 남는다.

## 3. MVP 사용자와 역할

첫 버전은 **1 파티장 : 1 파티원 : 1 정산 계약**으로 제한한다. 여러 파티원·대기열·패널티는 범위 밖이다.

### 파티장

- 정찰제 서비스와 정산 기간을 선택해 정산 조건을 만든다.
- 컨트랙트가 만든 참여 코드를 공유한다.
- 경과분만 `받을 돈`으로 인출한다.

### 파티원

- 유효한 참여 코드를 입력해 정산 조건을 확인한다.
- ERC-20 포인트를 승인하고 예치한다.
- 중단 시 남은 예치금을 환불받는다.

## 4. 핵심 사용자 흐름

### 4.1 파티장 흐름

1. MetaMask를 연결한다.
2. `새 정산 만들기`를 누른다.
3. `파티장으로 시작`을 고른다.
4. 서비스 정찰제, 기간, 수령 지갑을 확인한다.
5. 정산 계약을 생성하고 난수 참여 코드를 받는다.
6. 참여 코드와 정산 조건을 파티원에게 보낸다.
7. 파티원의 예치 후, 시간이 지난 만큼 `받을 돈`을 인출한다.

### 4.2 파티원 흐름

1. MetaMask를 연결한다.
2. `새 정산 만들기`에서 `파티원으로 참여`를 고른다.
3. 참여 코드를 입력한다.
4. 코드가 유효하면 서비스, 고정 금액, 기간, 파티장 지갑을 확인한다.
5. `Approve` 후 `예치하고 정산 시작`을 실행한다.
6. 대시보드에서 `남은 예치금`과 기간 진행률을 확인한다.
7. 필요하면 정산을 중단해 남은 예치금을 환불받는다.

### 4.3 참여 코드 규칙

- 계약 하나당 무작위 코드 하나를 생성한다.
- 파티원 한 명이 예치하면 코드는 즉시 사용 완료 상태가 된다.
- 존재하지 않거나 사용 완료·만료된 코드는 빨간 안내 문구로 거절한다.
- 파티장이 코드를 생성한 뒤에는 서비스명, 고정 금액, 기간을 변경할 수 없다.

## 5. 대시보드 정보 구조

대시보드는 OTT 카탈로그나 파티 탐색 화면이 아니다. 사용자가 “내 예치금이 지금 어떻게 분배되고 있는가?”를 확인하는 화면이다.

### 전역 셸

- 좌측 사이드바: `정산 현황`, `새 정산 만들기`, `거래 내역`
- 상단 바: 현재 네트워크, 지갑의 포인트 잔액, MetaMask 연결 또는 축약 지갑 주소
- 메인 헤더: `정산 현황`, 보조 설명, `새 정산 만들기` CTA

### 대시보드 본문

1. **컨트랙트에 묶인 돈** — 사용자의 진행 중 계약에 예치된 포인트 합계
2. **받을 돈** — 파티장 역할에서 즉시 인출 가능한 누적 금액
3. **남은 예치금** — 파티원 역할에서 지금 중단하면 돌려받을 수 있는 미경과 금액
4. **진행 중인 정산** — 서비스 아이콘, 역할, 경과 기간, 역할별 핵심 금액, 상세 버튼이 있는 가로형 계약 목록

OTT 아이콘과 서비스 이름은 목록에서만 보여 준다. 특정 OTT를 메인 카드로 강조하지 않는다.

### 정산 상세 화면

- 서비스명과 역할 배지
- 시작일, 종료일, 전체 기간, 진행률
- 총 예치금, 받을 돈, 남은 예치금
- 파티장: `받을 돈 인출`
- 파티원: `정산 중단하고 환불`
- 이벤트/거래 내역 타임라인

### 새 정산 모달과 후속 화면

- 첫 단계: `파티장으로 시작` / `파티원으로 참여`
- 파티장: 서비스 정찰제와 기간을 확인해 계약 생성 → 참여 코드 표시
- 파티원: 참여 코드 입력 → 조건 검증 → `Approve` → 예치

## 6. 문구 원칙

금융·블록체인 용어보다 사용자가 바로 이해할 표현을 우선한다.

| 피할 표현 | 사용할 표현 | 보조 설명 |
|---|---|---|
| 인출 가능 금액 | 받을 돈 | 파티장으로 지금 받을 수 있어요. |
| 환불 가능 금액 | 남은 예치금 | 지금 중단하면 돌려받아요. |
| Escrow balance | 컨트랙트에 묶인 돈 | 아직 누구에게도 완전히 지급되지 않았어요. |
| Stream | 정산 | 기간에 따라 나뉘는 계약이에요. |

## 7. 시각 설계 방향

`DESIGN-cohere.md`에서는 다음 원칙만 참고한다: 흰 여백, 딥 그린의 제품 영역, 얇은 구분선, 절제된 카드, 큰 정보 위계, 그림자보다 표면 대비로 만드는 깊이.

다음은 사용하지 않는다.

- Cohere의 이름, 로고, 고유 폰트, 실제 UI 복제
- 순수 검정, 보라-파랑 그라데이션, 과한 그림자
- 메인을 채우는 동일 크기 카드 3개

한국어 UI의 기본 폰트는 **Pretendard**다. 색상은 흰 캔버스, 깊은 녹색, 약한 스톤 표면, 단일 녹색 액센트로 구성한다. 데이터는 고정폭 숫자로 보여 주며, 모든 상태는 색상 외에도 문구로 구별한다.

## 8. 스마트컨트랙트 경계

### 온체인

- Mock ERC-20 포인트의 승인과 예치
- 총액, 시작 시각, 종료 시각, payer, payee 저장
- 경과 시간 기반 `earned`, `withdrawable`, `refundable` 계산
- 파티장 인출과 파티원 취소·환불
- 생성·예치·인출·취소 이벤트

### 오프체인/UI

- 서비스 정찰제 카탈로그
- 난수 참여 코드와 코드 상태
- 지갑 연결, 계약 조회, 트랜잭션 피드백
- 로컬 체인에서 발표용 시간 이동

참여 코드는 MVP에서는 UI 저장소의 계약 ID 매핑이다. 상용화에서 조작 방지 참여 코드가 필요하면 온체인 해시 또는 서버 서명 방식으로 확장한다.

## 9. 검증 시나리오

1. 파티원이 30일/10,000P 정산에 참여해 포인트를 예치한다.
2. 로컬 체인이 15일 앞으로 이동한다.
3. 화면과 컨트랙트는 `받을 돈 5,000P`, `남은 예치금 5,000P`를 표시한다.
4. 파티장이 5,000P를 인출한다.
5. 파티원이 중단하면 남은 5,000P가 환불되고 정산은 종료된다.
6. 잘못된 참여 코드는 예치 단계에 들어가지 못하고 오류 문구를 표시한다.

## 10. 제외 범위와 후속 계획

이번 MVP에서는 실제 OTT 계정 공급, 공식 API/제휴, 여러 파티원, 대기열, 자동 충전, 취소 패널티, 자동 접근 권한 회수를 구현하지 않는다.

후속 기능은 아래 순서로 검토한다.

1. 서비스별 정찰제 카탈로그와 참여 코드 만료
2. 여러 파티원과 정산 좌석 수
3. 대기자 교체와 잔여 기간 처리
4. 사용자 한도 기반 자동 포인트 충전
5. 공식 OTT 제휴 또는 이용권 API 연동
